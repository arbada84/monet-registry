# 컬처피플 3번째 사이트 타입 Claude 메인 화면 개편 기획서

- 대상 서비스: CulturePeople
- 대상 사이트 타입: `culturepeople`
- 대상 화면: 공개 메인 `/`
- 문서 상태: 디자인·개발 착수 전 기획
- 작성 기준일: 2026-07-26
- 구현 상태: 미구현

## 1. 목적

컬처피플 메인을 단순한 기사 카드 모음에서 벗어나, 방문자가 첫 화면에서 오늘의 핵심 문화 이슈를 이해하고 관심 기사로 자연스럽게 이동할 수 있는 모바일 우선 문화 뉴스 홈으로 개편한다.

이번 작업의 핵심은 장식적인 재디자인이 아니라 다음 세 가지다.

1. 컬처피플만의 시각적 정체성을 만든다.
2. 기사 탐색 속도와 모바일 가독성을 높인다.
3. 현재의 SEO, 광고, 게시 상태, 카테고리, 운영 배포 구조를 깨지 않는다.

메인의 단일 핵심 과업은 다음과 같이 정의한다.

> 방문자가 10초 안에 오늘의 주요 문화 이슈를 파악하고 읽을 기사 한 건을 선택하게 한다.

## 2. 3번째 사이트 타입 확인

현재 사이트 타입은 `src/lib/site-type.ts`에 다음 순서로 정의돼 있다.

1. `netpro`
2. `insightkorea`
3. `culturepeople`

따라서 이 문서에서 말하는 “컬처피플 3번째 사이트 타입”은 별도의 신규 타입을 추가하는 것이 아니라 기존 `culturepeople` 전용 테마를 개편하는 작업이다.

현재 메인 분기:

```tsx
siteType === "culturepeople"
  ? <CulturePeopleLanding />
  : siteType === "insightkorea"
    ? <InsightKoreaLanding />
    : <CulturepeopleLanding />
```

개편 시 지켜야 할 격리 원칙:

- `netpro`와 `insightkorea` 화면은 수정하지 않는다.
- `cp-site-type` 저장값과 기본값 `culturepeople`을 바꾸지 않는다.
- 신규 이름 `culturepeople-v3`를 사이트 타입에 추가하지 않는다.
- 디자인 버전 전환이 필요하면 사이트 타입이 아니라 별도 홈 variant로 관리한다.

## 3. 현재 구조

### 3.1 주요 파일

| 역할 | 현재 파일 |
|---|---|
| 메인 라우트와 데이터 조회 | `src/app/page.tsx` |
| 사이트 타입 판별 | `src/lib/site-type.ts` |
| 컬처피플 메인 | `src/components/themes/culturepeople/CulturePeopleLanding.tsx` |
| 헤더·검색·모바일 메뉴 | `src/components/themes/culturepeople/CulturePeopleHeader.tsx` |
| 푸터·법적/회사 정보 | `src/components/themes/culturepeople/CulturePeopleFooter.tsx` |
| 기사 타입 | `src/types/article.ts` |
| 표준 카테고리 | `src/lib/culturepeople-categories.ts` |
| 광고 슬롯 | `src/components/ui/AdBanner.tsx`, `CoupangAutoAd.tsx` |
| 공개 스모크 | `scripts/browser-smoke.mjs` |

### 3.2 현재 메인 데이터 흐름

- `/`에서 최대 240건의 홈 기사를 조회한다.
- `culturepeople`일 때 전체 기사 배열을 클라이언트 랜딩 컴포넌트로 전달한다.
- 랜딩에서 `게시` 기사만 다시 필터링한다.
- 최신 4건을 히어로로 사용한다.
- 히어로를 제외한 기사를 카테고리별 최대 4건씩 노출한다.
- 헤더와 푸터는 일부 설정을 브라우저에서 다시 조회한다.

### 3.3 현재 장점

- 사이트 타입별 테마 분리가 이미 존재한다.
- 게시 상태 필터와 기사 `no` 우선 URL 규칙이 있다.
- `next/image`의 `fill`, hero `priority`, 반응형 `sizes`를 사용한다.
- 모바일 메뉴, 검색 오버레이, 포커스 복귀 처리가 있다.
- 카테고리와 사이트 설정을 서버에서 초기 전달한다.
- 모바일 첫 뉴스 영역보다 중간 광고가 먼저 나오지 않도록 한 기존 개선이 있다.

### 3.4 현재 개선 대상

1. `CulturePeopleLanding.tsx`가 큰 클라이언트 컴포넌트라 기사 데이터와 화면 로직이 한 파일에 결합돼 있다.
2. 보라색 계열 하드코딩이 헤더·랜딩·푸터에 반복돼 한 가지 색조로 읽힌다.
3. 모든 카테고리가 같은 모양으로 반복돼 페이지가 길고 단조롭다.
4. 메인 기사 이미지 위에 많은 텍스트를 겹쳐 이미지와 제목 모두 빠르게 읽기 어렵다.
5. 데스크톱 헤더 로고 영역이 크고 첫 기사까지 도달하는 거리가 길다.
6. 모바일 히어로가 터치 이벤트 기반 수동 구현이며 키보드·스크린리더 맥락이 약하다.
7. 모바일에서 작은 글자와 작은 슬라이드 점을 사용한다.
8. `home-mid-2` 광고 슬롯은 `src/app/page.tsx`에서 전달하지만 현재 컬처피플 랜딩에서 사용하지 않는다.
9. `home-mid-1`과 쿠팡 영역이 같은 지점에 연속 배치될 수 있다.
10. 헤더와 푸터에 동일한 브랜드 SVG와 색상 상수가 중복돼 있다.
11. 이미지가 없는 기사 fallback이 영문 `No Image`이고 시각적 크기가 일관되지 않다.
12. 과거 캡처와 현재 코드가 섞여 있으므로 구현 전 최신 로컬 기준 캡처를 다시 만들어야 한다.

## 6. 디자인 방향

### 6.1 디자인 명칭

**Culture Program**

공연 프로그램 북과 문화 행사 편성표에서 착안한 구조다. 신문 복제품이나 마케팅 랜딩이 아니라, 이미지가 강한 문화 콘텐츠와 짧은 뉴스 탐색을 함께 처리하는 현대적인 편집 화면을 목표로 한다.

### 6.2 디자인 문장

> 무대의 중심을 보여주는 한 장의 대표 이미지와, 관객이 다음 순서를 빠르게 고를 수 있는 정돈된 프로그램 목록.

### 6.3 고유한 시각 요소

대표 이미지와 최신 기사 목록이 하나의 세로 기준선에 맞춰지는 **Culture Cutline**을 메인의 시각적 서명으로 사용한다.

- 장식용 구체, 보라색 원, 무의미한 숫자 장식을 추가하지 않는다.
- 기준선은 이미지, 제목, 카테고리, 최신 기사 시간을 정렬하는 구조로만 사용한다.
- 기존 네 개 원 형태는 브랜드 로고에서만 유지한다.

### 6.4 피해야 할 방향

- 보라색만 여러 명도로 사용하는 단색 UI
- 크림 배경과 세리프만으로 만든 전형적인 AI 매거진
- 검은색 배경과 네온 포인트
- 전통 신문 지면을 그대로 복제한 빽빽한 broadsheet
- 둥근 카드가 계속 중첩되는 SaaS형 화면
- 큰 마케팅 문구나 서비스 소개 hero
- 모든 섹션의 과도한 스크롤 애니메이션
- 이미지 위에 긴 제목·요약·날짜를 모두 겹치는 방식

## 7. 디자인 토큰

토큰은 컬처피플 테마 내부 CSS 변수로 관리하고 컴포넌트에 raw hex를 반복하지 않는다.

### 7.1 색상

| 토큰 | 값 | 역할 |
|---|---:|---|
| `--cp-canvas` | `#F7F7F5` | 페이지 바탕 |
| `--cp-surface` | `#FFFFFF` | 콘텐츠 바탕 |
| `--cp-ink` | `#18161E` | 제목·주요 텍스트 |
| `--cp-copy` | `#4E4A55` | 본문·보조 텍스트 |
| `--cp-muted` | `#706B76` | 날짜·메타 정보 |
| `--cp-line` | `#DDD9E2` | 구분선 |
| `--cp-brand` | `#5B4B9E` | 로고·포커스·주요 링크 |
| `--cp-culture` | `#B83F5A` | 문화·엔터 계열의 제한적 표시 |
| `--cp-discovery` | `#16756E` | 라이프·테크 계열의 제한적 표시 |
| `--cp-highlight` | `#A66B08` | 중요 라벨·공공/비즈 계열 표시 |
| `--cp-danger` | `#B42318` | 오류 상태 전용 |

색상 사용 원칙:

- 바탕 면적은 canvas/surface/ink가 담당한다.
- 브랜드 보라는 전체 면적이 아니라 로고, 링크, focus ring, 얇은 기준선에만 사용한다.
- 카테고리 색은 텍스트·1~3px 선·작은 상태점에만 사용한다.
- 본문 텍스트 대비는 WCAG AA 4.5:1 이상이어야 한다.
- 색상만으로 카테고리나 상태를 구분하지 않고 텍스트 라벨을 함께 표시한다.

### 7.2 타이포그래피

| 역할 | 글꼴 | 기준 |
|---|---|---|
| 대표 기사 제목 | `Noto Serif KR` 600 후보 | 문화적 성격을 주되 대표 제목에만 제한 |
| 기사·내비게이션·본문 | 현재 `Noto Sans KR` 400/500/700 | 가독성과 기존 로딩 자산 유지 |
| 시간·날짜·영문 보조 | `Geist` 또는 시스템 sans | 숫자와 짧은 메타 정보 |

구현 전 `Noto Serif KR` 추가에 따른 폰트 용량과 LCP 영향을 비교한다. 성능 저하가 크면 대표 제목도 `Noto Sans KR` 700으로 통일한다.

타입 크기 기준:

- 본문과 기사 목록: 최소 14px, 모바일 주요 목록 15~16px
- 대표 제목: 모바일 26px/1.25, 데스크톱 38px/1.2
- 섹션 제목: 모바일 20px, 데스크톱 24px
- 메타 정보: 최소 12px
- viewport 너비에 비례한 `vw` 글자 크기는 사용하지 않는다.
- letter-spacing은 0을 기본으로 한다.

### 7.3 모서리·선·그림자

- 카드와 이미지 반경: 0~6px
- 버튼·입력 반경: 6px
- 섹션을 떠 있는 카드로 감싸지 않는다.
- 구분은 1px 선과 여백으로 처리한다.
- 그림자는 검색 오버레이와 모바일 메뉴처럼 레이어 구분이 필요한 곳에만 쓴다.

### 7.4 모션

- 기본 전환: 150~220ms
- 이미지 hover: 최대 `scale(1.02)`
- 메뉴·검색: opacity/translate 180~220ms
- 자동 재생 슬라이더와 parallax는 사용하지 않는다.
- `prefers-reduced-motion`에서는 이동·확대 효과를 제거한다.

```text
│ 첫 광고                    │ 뉴스 5~7건 뒤
├─────────────────────────────┤
│ 카테고리별 대표 + 목록     │
└─────────────────────────────┘
```

모바일에서는 자동·수동 히어로 swiper를 제거하고 대표 기사 한 건과 최신 기사 목록을 고정 노출하는 안을 우선한다. 콘텐츠 교체를 위해 사용자가 작은 점을 눌러야 하는 구조보다 스크롤 흐름이 예측 가능하고 접근성이 좋다.

## 9. 화면별 상세 사양

### 9.1 헤더

- 데스크톱 전체 높이를 현재보다 줄여 첫 기사 진입 거리를 단축한다.
- 로고는 기존 `public/logo-symbol.svg` 또는 공통 BrandMark 컴포넌트를 사용한다.
- 검색·메뉴·닫기 아이콘은 `lucide-react`를 사용한다.
- 데스크톱 내비게이션은 한 줄을 유지하되 공간이 부족하면 gap과 padding을 줄이고 텍스트를 축소하지 않는다.
- 모바일 메뉴·검색 버튼은 44×44px 이상으로 만든다.
- 검색 오버레이는 `role="dialog"`, 접근 가능한 이름, Escape 닫기, focus 복귀를 유지한다.
- 모바일 카테고리 바는 sticky 사용 시 본문을 가리지 않도록 실제 높이를 반영한다.
- 메뉴 안에 구현 설명이나 사용법 문구를 넣지 않는다.

### 9.2 대표 기사

- 실제 최신 `게시` 기사 중 유효한 `no`를 가진 첫 기사를 사용한다.
- 이미지와 텍스트를 분리해 제목 가독성과 이미지 확인성을 높인다.
- 이미지 위에는 긴 텍스트를 겹치지 않는다.
- 대표 이미지 컨테이너는 16:10 비율과 안정적 높이를 가져 CLS를 방지한다.
- 대표 기사 이미지만 `priority` 또는 `fetchPriority="high"`를 사용한다.
- 제목 2~3줄, 요약 2줄, 카테고리와 날짜를 노출한다.
- 이미지가 없으면 브랜드 그라데이션이 아니라 단색 바탕과 컬처피플 워드마크 fallback을 사용한다.

### 9.3 최신 기사 레일

- 대표 기사를 제외한 최신 4건을 사용한다.
- 데스크톱에서는 시간/카테고리/제목을 세로 목록으로 배치한다.
- 모바일에서는 최대 3건을 노출하고 나머지는 전체기사 링크로 연결한다.
- 썸네일은 선택 사항이며 사용하면 모든 행에 동일 크기를 예약한다.
- 각 행 전체가 링크가 되되 중첩 링크를 만들지 않는다.

### 9.4 지금 읽을 이야기

- 최신 기사만 반복하지 않고 대표 기사와 최신 레일에서 사용하지 않은 기사 3건을 노출한다.
- 별도의 추천 알고리즘이 없으므로 “인기”나 “에디터 추천”이라고 표시하지 않는다.
- 초기 명칭은 사실에 맞는 “지금 읽을 이야기”를 사용한다.
- 조회수 기반 정렬을 도입할 때만 “많이 본 기사”로 이름을 바꾼다.

### 9.5 카테고리 밴드

- 표준 카테고리 순서는 `CULTUREPEOPLE_CATEGORIES`를 기준으로 한다.
- 관리자에서 명시적으로 숨긴 카테고리는 노출하지 않는다.
- 카테고리당 최대 3~5건만 노출한다.
- 상단에서 사용된 기사 ID는 이후 섹션에서 다시 사용하지 않는다.
- 문화·엔터는 이미지 비중을 높이고, 테크·비즈·공공은 텍스트 스캔 밀도를 높인다.
- 각 섹션은 중첩 카드가 아니라 전체 폭 band와 구분선으로 구성한다.
- 기사 부족 시 빈 카드로 자리를 채우지 않고 레이아웃 열 수를 줄인다.

### 9.6 광고

- 광고 컴포넌트와 position 이름은 유지한다.
- `top`, `home-mid-1`, `home-mid-2`, `bottom`을 모두 명시적으로 소비한다.
- 모바일에서는 대표 기사와 최신 기사 5~7건 전에 광고를 넣지 않는다.
- `home-mid-1`, `home-mid-2`, Coupang 광고가 연속해서 나타나지 않게 기사 band 하나 이상을 사이에 둔다.
- 광고 컨테이너는 예상 높이를 예약해 CLS를 줄인다.
- 광고 로드 실패 시 빈 큰 공간을 무기한 남기지 않는 기존 정책을 점검한다.
- 광고 iframe의 외부 오류는 warning으로 취급하되 동일 출처 오류는 smoke 실패로 유지한다.

### 9.7 푸터

- 법적 링크와 회사 정보의 내용은 변경하지 않는다.
- 값이 없는 필드는 임의 이름이나 번호로 채우지 않는다.
- 긴 링크 목록은 데스크톱 2행 이하, 모바일 논리적 그룹으로 정리한다.
- 개인정보처리방침 등 중요한 링크는 색상뿐 아니라 font weight로도 구분한다.
- 파트너 안내는 실제 운영 정보가 확인될 때만 유지하며, 하드코딩 이메일은 관리자 설정과 대조한다.
- 푸터가 메인만의 별도 회사 정보를 만들지 않게 기존 fallback 계약을 유지한다.

## 10. 데이터 선택 규칙

메인 레이아웃은 순수 함수로 분리해 테스트할 수 있게 한다.

후보:

```ts
buildCulturePeopleHomeLayout({
  articles,
  categories,
  limits,
})
```

반환 후보:

```ts
{
  lead: Article | null;
  latest: Article[];
  discovery: Article[];
  categoryBands: Array<{
    category: string;
    variant: "visual" | "balanced" | "compact";
    articles: Article[];
  }>;
}
```

필수 규칙:

1. `status === "게시"`만 사용한다.
2. `deletedAt`이 있는 기사는 사용하지 않는다.
3. 유효한 기사 `no`를 우선 URL로 사용한다.
4. 동일 기사 ID/no는 메인 한 화면에서 한 번만 사용한다.
5. 대표 기사와 LCP 이미지 결정은 서버 렌더 시 확정한다.
6. 기사·카테고리가 부족해도 페이지가 오류 없이 축소된다.
7. 제목·요약·카테고리 문자열은 UI에서 HTML로 해석하지 않는다.
8. 이미지 alt는 `thumbnailAlt || title`을 사용한다.
9. 원본 기사 순서를 임의로 섞지 않는다.
10. 운영 DB 쓰기 없이 조회 결과만 가공한다.

| 대형 모바일 | 430px | 제목 잘림 없음, 광고 순서 정상 |

텍스트, 이미지, 광고, 로딩 상태가 동적으로 바뀌어도 고정 형식 요소의 크기가 흔들리지 않도록 `aspect-ratio`, grid track, min/max width를 명시한다.

## 13. 접근성 완료 기준

- 문서에 하나의 논리적 `h1` 또는 화면의 대표 제목 계층을 정한다.
- 이후 섹션은 `h2`, 기사 제목은 `h3` 순서를 유지한다.
- 본문으로 건너뛰기 링크를 제공한다.
- 모든 메뉴·검색·닫기 컨트롤에 접근 가능한 이름이 있다.
- 아이콘 버튼은 최소 44×44px이다.
- 키보드만으로 메뉴, 검색, 기사 링크, 광고 다음 콘텐츠로 이동할 수 있다.
- search dialog와 mobile sheet에 focus trap 또는 동등한 focus 관리가 있다.
- focus ring은 보라색 2px 이상으로 분명하게 보인다.
- 이미지 alt와 fallback이 있다.
- 자동 재생 콘텐츠가 없다.
- `prefers-reduced-motion`을 따른다.
- 200% 확대에서도 텍스트와 버튼이 겹치지 않는다.

## 14. 성능 기준

- 대표 이미지 한 장만 우선 로드한다.
- below-the-fold 이미지는 lazy loading을 유지한다.
- 이미지 `sizes`가 실제 grid 폭과 일치해야 한다.
- 메인에 전달하는 기사 수와 JSON hydration 크기를 측정해 줄인다.
- 목표 렌더 기사 수는 약 35~50건이며, 실제 카테고리 부족 시 더 적게 전달한다.
- 광고 슬롯에는 예약 높이를 둔다.
- layout shift 목표: CLS 0.1 미만.
- 모바일 LCP 목표: 운영 환경 p75 2.5초 이내를 지향하되 광고·외부 이미지 조건을 별도 기록한다.
- 단순 디자인을 위해 GSAP 같은 신규 대형 런타임 의존성을 추가하지 않는다.
- `framer-motion`도 메인 개편에서 필요성이 명확하지 않으면 사용하지 않는다.

## 15. SEO·운영 불변 조건

- 홈 canonical은 `https://culturepeople.co.kr`을 유지한다.
- `NewsMediaOrganization`과 `SearchAction` JSON-LD를 유지한다.
- 게시 기사 URL은 `/article/{no}`를 사용한다.
- 삭제·미게시 기사 404와 NOINDEX 정책을 변경하지 않는다.
- sitemap, news-sitemap, RSS, IndexNow 코드를 건드리지 않는다.
- 뉴스레터 위젯을 메인에 다시 연결하지 않는다.
- auto-news 중지와 auto-press 운영 상태에 영향을 주지 않는다.
- 홈페이지 데이터 조회 실패 시 빈 화면 대신 안전한 축소 UI를 유지한다.
