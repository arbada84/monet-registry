# 일간보고 접속 증가 분석

확인일: 2026-10-14, Asia/Seoul. 운영 D1 읽기 전용 집계, 보고서/조회 추적 코드, 공개 설정과 Worker health를 확인했다. 운영 DB 변경, 보고서 재발송, 배포는 하지 않았다. 원 IP, visitor hash, Telegram chat ID, secret을 보고서에 포함하지 않았다.

## 결론

기사 조회 기록과 방문 식별값의 증가 자체는 운영 DB에서도 확인된다. 현재 수치를 잘못 더하거나 조회 로그를 방문자로 대체한 흔적은 최근 확인 구간에 없다. 그러나 이 식별값은 실제 사람을 인증한 값이 아니므로 실제 사람 유입 증가 또는 봇 증가 중 하나로 확정할 수 없다.

| --- | ---: | ---: |
| 10-07 | 9 | 9 |

| 10-09 | 1 | 1 |
| 10-10 | 3 | 3 |

9월 30일~10월 6일은 하루 3~20개 식별값이었다. 10월 11일 이후 증가가 확인된다. Worker의 10월 13일 보고서 전송 완료 기록도 존재한다. 전송된 메시지 본문 자체는 저장되어 있지 않아 사용자 Telegram 메시지의 숫자/항목과 직접 대조한 것은 아니다.

최근 3일의 식별값 누락은 0건이다. 하루 식별값별 최대 조회는 각각 6/3/4건이고, 각 식별값의 하루 최초~최종 기록이 60초 이하이면서 3건 이상인 경우는 0건이었다. 이 검사는 일일 span을 사용한 제한된 휴리스틱이다. 장시간 접속 중 일부 구간의 burst나 IP를 바꾸는 자동화까지 배제하지 않는다.

## 집계의 한계

- `article-view`는 기사 화면의 JavaScript POST 기록이다. 전체 HTTP 요청, 홈만 읽은 방문, JavaScript를 실행하지 않는 일반 크롤러를 모두 세는 통계가 아니다.
- 방문 식별값은 KST 날짜 + IP + User-Agent + salt를 해시한다. 한 사람도 IP/브라우저/기기가 달라지면 여러 식별값이 되고, 같은 IP/브라우저를 공유하면 여러 사람이 합쳐질 수 있다.
- 봇은 User-Agent 문자열 패턴으로 판별한다. 빈 User-Agent와 일반 Chrome처럼 보이는 자동화는 비봇으로 분류될 수 있다. 확인 구간의 봇 로그 0건은 봇 접속이 없다는 증거가 아니다.
- Worker의 `human_visitors || human_views`, Next 보고서의 식별키가 모두 없을 때 로그 수로 대체하는 로직은 조회 수를 방문자 수처럼 표시할 위험이 있다. 최근 구간은 키가 모두 있어 이번 증가의 직접 원인은 아니다.
- 서버 메모리의 10분 중복 억제는 서버리스 인스턴스 간 공유되지 않는다. D1에는 같은 기사/식별값/봇 상태의 5분 중복 조회 검사가 별도로 존재한다. 요청의 완전한 동시 중복 방지는 별도 검토가 필요하다.
- 인기 기사 `views`는 기사에 저장된 누적 조회다. 일일 사람 수가 아니며 이전 데이터 이전/가져오기 수치를 포함할 수 있다.

운영 `cp-seo-settings`의 GA4/네이버 애널리틱스 ID는 미설정이었다. GA4 실제 사용자, 검색 유입, 유입 국가/경로와 교차 검증하지 못했다. 조회 로그에도 원 User-Agent/referrer를 보관하지 않아 과거 접속을 정확히 재분류할 근거가 부족하다.

## 개선 우선순위

1. `순수 방문자`를 `기사 방문 식별값(추정)`으로 바꾸고 기사 조회 로그와 구분한다. 식별값이 없을 때 조회 수를 방문자 수로 대체하지 말고 `집계 불가`와 누락 건수를 표시한다.
2. 비봇 판정은 실제 사람 인증이 아니라는 설명을 보고서에 추가한다. 빈/미분류 User-Agent를 정상 사람으로 단정하지 않는 분류를 검토한다.
3. GA4 설정과 실제 수집 여부를 확인하고 같은 KST 날짜의 기사 이벤트/사용자/검색 유입과 대조한다. 개인정보 처리와 동의 요건 검토 없이 새 추적을 활성화하지 않는다.
4. 증거 수집을 추가할 경우 원 IP/전체 User-Agent를 무조건 저장하지 말고 제한된 브라우저 유형/자동화 신호/유입 도메인 집계, 보관 기간과 접근 권한을 먼저 정한다.

계산 숫자를 임의로 낮추거나 과거 로그를 삭제하지 않는다. 분석 요청이므로 이번에는 집계 코드/수집 정책을 변경하지 않았다.
