# Phase 20-01 Plan: Env-first SMTP resolver

**Status:** Complete 2026-05-25.

## Goal

Create one server-only SMTP configuration resolver that uses Vercel environment variables first and adopt it across SMTP send/test paths without changing visible newsletter behavior.

## Context

SMTP credentials are currently read from `cp-newsletter-settings` in several places. The admin settings API masks `smtpPass`, but the production credential can still depend on database settings. v4.0 moves the operational secret source to environment variables while keeping DB settings as a compatibility fallback during migration.

## Tasks

1. Add a server-only SMTP resolver.
   - Read `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_SECURE`, `SMTP_SENDER_EMAIL`, `SMTP_SENDER_NAME`, and `SMTP_REPLY_TO_EMAIL` from environment variables.
   - Merge safe non-secret DB settings for fallback and display metadata.
   - Return a safe status object that never includes `SMTP_PASS`.

2. Adopt the resolver in server paths.
   - `/api/newsletter/send`
   - `notifyNewsletterOnPublish`
   - auto-news AI failure notification
   - `/api/smtp/test`

3. Add focused tests.
   - Env values win over DB settings.
   - Missing password returns an operator-safe error.
   - Safe status masks secret source and never returns raw password.

## Non-Goals

- Do not remove DB settings UI in this plan.
- Do not delete existing DB `smtpPass` values automatically.
- Do not change newsletter subscriber behavior.

## Acceptance Criteria

- [x] All targeted send/test paths use the shared resolver.
- [x] No route returns or logs raw SMTP password values.
- [x] Focused unit tests and `pnpm check:planning` pass.
