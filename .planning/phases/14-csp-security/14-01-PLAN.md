# Phase 14-01 Plan: nonce-based script CSP

## Goal

Replace the current static script CSP with per-request nonce-based CSP while preserving existing analytics, ads, and public/admin page behavior.

## Tasks

1. Add CSP helper module.
   - Create `src/lib/security/csp.ts`.
   - Export `createCspNonce()` and `buildContentSecurityPolicy()`.
   - Keep script host allowlist explicit.
   - Include `'unsafe-eval'` only outside production.

2. Move CSP ownership to middleware.
   - Remove static `Content-Security-Policy` from `next.config.ts`.
   - Generate one nonce per middleware pass.
   - Forward `x-nonce` and `x-pathname` as request headers.
   - Set `Content-Security-Policy` on normal `NextResponse.next()` responses.
   - Expand middleware matcher to public pages while excluding static assets.

3. Apply nonce in app layout.
   - Read `x-nonce` through `headers()`.
   - Add `<meta name="csp-nonce" content={nonce}>`.
   - Pass `nonce={nonce}` to GA, Naver, AdSense, and Kakao `Script` components.

4. Support dynamic ad scripts.
   - Update `ScriptUnit` to read the nonce meta tag.
   - Add the nonce to external and vetted inline scripts it inserts.

5. Add tests and run full verification.
   - Add unit tests for CSP builder.
   - Run `tsc`, unit tests, lint, validation, automation guard, build.
   - Deploy and verify live headers.

## Non-Goals

- Do not remove `style-src 'unsafe-inline'` yet; current UI has extensive inline React styles.
- Do not rewrite all admin/public style attributes in this phase.
- Do not use CSP report collection until baseline enforcement is stable.

## Acceptance Criteria

- `script-src` contains a nonce token.
- `script-src` does not contain `'unsafe-inline'`.
- Production `script-src` does not contain `'unsafe-eval'`.
- Existing GA/Naver/AdSense/Kakao `Script` tags receive the nonce.
- Build and targeted tests pass.
