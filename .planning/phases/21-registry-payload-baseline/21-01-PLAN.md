# Phase 21-01 Plan: Registry Payload Baseline And CI Guard

**Date:** 2026-05-25
**Milestone:** v5.0 Registry Payload And API Weight Reduction
**Status:** Complete

## Goal

Measure the current generated registry payload and add a low-risk guard that catches accidental payload growth before deeper artifact splitting begins.

## Scope

- Add a script that reads generated registry artifacts and reports byte, gzip, entry, searchable text, and largest component metrics.
- Check a committed baseline file with thresholds that are above current values but tight enough to reveal accidental growth.
- Add the registry payload check to `pnpm ci:all`.
- Update planning state so v5.0 starts from the Linux-native working tree.

## Implementation

- `scripts/registry-payload-report.mjs`
  - Reads `public/generated/registry.json`, `registry.json`, `page-registry.json`, `category-index.json`, `tag-index.json`, `page-index.json`, and `section-to-page.json`.
  - Prints a human-readable report by default and supports `--json`.
  - Supports `--check`, loading `docs/registry-payload-baseline.json` and failing on threshold violations.
- `docs/registry-payload-baseline.json`
  - Stores measured v5.0 baseline values and initial thresholds.
- `package.json`
  - Adds `registry:payload-report` and `check:registry-payload`.
  - Includes `check:registry-payload` in `ci:all`.

## Verification

- `node --check scripts/registry-payload-report.mjs`
- `pnpm registry:payload-report`
- `pnpm check:registry-payload`
- `pnpm check:planning`
- `git diff --check`

## UAT

- Operator can run `pnpm registry:payload-report` and see the current registry payload baseline.
- CI fails if generated registry payload exceeds the baseline thresholds.
- Existing production API behavior remains unchanged because this plan only adds measurement and checks.
