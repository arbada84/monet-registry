# Phase 17-03 Plan: health endpoint and preflight readiness verification

## Goal

Close `AUTO-07` by verifying that `/api/auto-press/health` reports AI, D1/database, R2/media, Worker, retry scheduler, observability, and source readiness in a form operators can act on before running or retrying auto-press jobs.

## Context

Phase 17-01 stabilized manual run control APIs and Phase 17-02 locked the dashboard UX. The health endpoint already reports database, AI, media storage, observability, retry scheduler, and Worker status. This phase adds explicit source readiness so operators can catch missing RSS feed targets before a manual run starts.

## Tasks

1. Audit `/api/auto-press/health`.
   - Confirm authenticated-only access.
   - Confirm D1/Supabase provider readiness.
   - Confirm AI provider/key readiness without exposing secrets.
   - Confirm media storage readiness including remote/write probes.
   - Confirm Worker and retry scheduler readiness.
   - Confirm observability and retry queue summary readiness.

2. Add source readiness.
   - Count configured sources.
   - Count enabled sources.
   - Count enabled sources that have fetch targets.
   - Return warning/error detail for enabled sources missing RSS feed URLs.

3. Add tests.
   - Healthy response includes database, AI, media, Worker, retry scheduler, observability, retry queue, and source readiness.
   - Missing source fetch targets make health return an operator-visible error without leaking AI keys.

4. Extend agent-loop verification.
   - Guard health readiness checks for database, AI, media, Worker, retry scheduler, observability, retry queue, and sources.

5. Run verification.
   - `pnpm test:unit tests/unit/auto-press-observability-routes.test.ts`
   - `pnpm check:auto-press-agent-loop`
   - `pnpm check:planning`
   - `pnpm ci:typecheck`
   - `pnpm ci:lint`
   - `pnpm build`

## Non-Goals

- Do not perform live remote Worker or RSS probes by default.
- Do not change retry queue processing behavior; Phase 18-01 covers retry queue processor verification.
- Do not deploy or apply D1/Worker changes.
- Do not expose provider keys, Worker secrets, tokens, or environment secrets in health responses.

## Acceptance Criteria

- `/api/auto-press/health` distinguishes database, AI, media storage, Worker, retry scheduler, observability, retry queue, and source readiness.
- Enabled sources without RSS feed targets are operator-visible.
- Health tests cover both ready and source-not-ready states.
- Agent-loop, planning, typecheck, lint, and build checks pass.
