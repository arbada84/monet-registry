# Phase 17-01 Plan: manual run processor and continuation verification

## Goal

Close `AUTO-05` by making manual auto-press execution easy to start, poll, continue, cancel, and retry at item level through explicit API contracts.

## Context

Phase 16 completed D1 observability and reconciliation. Phase 17 moves up to the operator-facing manual run workflow. The code already has routes for run creation, run detail polling, continuation, cancellation, and item retry. This plan verifies and tightens the contract so the dashboard and later Telegram/operator tools can rely on stable IDs.

## Tasks

1. Audit manual run routes.
   - `POST /api/auto-press/runs`
   - `GET /api/auto-press/runs/[id]`
   - `POST /api/auto-press/runs/[id]/process`
   - `POST /api/auto-press/runs/[id]/cancel`
   - `POST /api/auto-press/items/[id]/retry`

2. Make response contracts explicit.
   - Return `runId` from run creation.
   - Return `runId` and `previousRunId` from continuation.
   - Return `runId` from cancellation.
   - Return `itemId` and `queueId` from item retry.

3. Preserve continuation options.
   - Keep `executionMode` from the previous observed run unless explicitly overridden.
   - Keep `maxCandidates` from the previous observed run unless explicitly overridden.
   - Continue excluding previously attempted source URLs.

4. Add route tests.
   - Manual run creation returns a pollable run ID.
   - Run detail route supports polling.
   - Continuation preserves execution mode and excludes attempted URLs.
   - Cancellation returns a run ID.
   - Item-level retry returns queue ID and routes through the retry scheduler.

5. Run targeted verification.
   - `pnpm test:unit -- auto-press-observability-routes`
   - `pnpm check:auto-press-agent-loop`
   - `pnpm check:planning`
   - `pnpm ci:typecheck`

## Non-Goals

- Do not redesign `/cam/auto-press`; dashboard UX verification is Phase 17-02.
- Do not change health readiness checks; that is Phase 17-03.
- Do not deploy or apply D1 migrations.
- Do not remove `cp-auto-press-history` compatibility writes.

## Acceptance Criteria

- Manual run APIs expose stable IDs for polling and follow-up actions.
- Continuation keeps queue/batch execution semantics rather than silently changing mode.
- Item retry exposes the created retry queue ID to the caller.
- Route tests cover creation, polling, continuation, cancellation, and item-level retry.
