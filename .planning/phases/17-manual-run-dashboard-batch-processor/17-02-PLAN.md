# Phase 17-02 Plan: auto-press admin dashboard UX verification

## Goal

Close `AUTO-06` by verifying that `/cam/auto-press` exposes the operator views needed to understand and recover auto-press runs without leaking credentials into the client dashboard.

## Context

Phase 17-01 made manual run APIs pollable and controllable with stable IDs. The dashboard already contains tabs for observed runs, item results, retry queue, DLQ, and health. This phase locks that operator UX into unit and agent-loop checks so future edits cannot silently remove key panels, API loaders, action handlers, or secret hygiene.

## Tasks

1. Audit `/cam/auto-press`.
   - Confirm tabs for run status, item results, AI retry queue, DLQ, system health, and settings/history remain present.
   - Confirm D1 observability loaders fetch run summaries, run events, item rows, source quality, retry queue, DLQ, and health.

2. Verify operator actions are reachable.
   - Continue a run from the run table.
   - Mark a run cancelled.
   - Retry an observed item.
   - Retry or cancel a retry queue entry.
   - Requeue or discard a DLQ item.

3. Verify visible operator context.
   - Run reason summary.
   - Event timeline.
   - Item result table.
   - Source quality report.
   - Retry queue and DLQ summary.
   - Health quick, remote, write, and retry-scheduler controls.

4. Add static dashboard regression coverage.
   - Create a focused unit test for dashboard tabs, loaders, actions, labels, and secret references.
   - Extend `pnpm check:auto-press-agent-loop` with the same dashboard coverage.

5. Run verification.
   - `pnpm test:unit tests/unit/auto-press-dashboard-ui.test.ts`
   - `pnpm check:auto-press-agent-loop`
   - `pnpm check:planning`
   - `pnpm ci:typecheck`
   - `pnpm ci:lint`
   - `pnpm build`

## Non-Goals

- Do not redesign the dashboard layout.
- Do not change health endpoint semantics; Phase 17-03 covers health readiness.
- Do not deploy or modify live Cloudflare/D1 resources.
- Do not expose any provider key, worker secret, token, or environment secret in the client page.

## Acceptance Criteria

- `/cam/auto-press` has guarded coverage for summaries, recent events, item results, retry queue, DLQ, source quality, and health.
- Operator recovery actions remain wired from the dashboard.
- The dashboard source does not reference known secret field names or environment secret variables.
- Targeted tests and agent-loop checks pass.
