# Phase 15-01 Plan: auto-press baseline audit and failure hardening

## Goal

Bring the existing auto-press observability, retry queue, DLQ, Worker, and Telegram implementation under v3.0 planning, then close any gaps where AI configuration failures can still become unhandled 500s.

## Context

The codebase already contains v3-shaped auto-press surfaces:

- `/api/auto-press/runs`, `/items`, `/retry-queue`, `/dlq`, `/health`, `/worker-notify`
- `src/lib/auto-press-observability.ts`
- `src/lib/auto-press-retry-queue.ts`
- `src/lib/auto-press-worker-dispatch.ts`
- Telegram command/report helpers
- Cloudflare auto-press Worker and retry scheduler scripts

Phase 15 is therefore a baseline audit and hardening phase rather than a greenfield build.

## Tasks

1. Map current implementation to v3.0 requirements.
   - List the runtime/API/test files that satisfy `AUTO-01` and `AUTO-02`.
   - Identify any direct auto-press path that can still throw before producing a structured run/item failure.
   - Confirm Linux baseline commit and validation commands are captured in planning state.

2. Audit AI settings failure handling.
   - Review `runAutoPress`, retry queue processing, health route, Telegram summaries, and worker notify paths.
   - Ensure missing settings are distinguishable from missing provider keys.
   - Standardize reason codes as `NO_AI_SETTINGS` or `NO_AI_KEY`.

3. Add or adjust tests for failure mapping.
   - Cover auto-press run snapshots or retry queue entries created after AI key/settings failures.
   - Cover operator-facing route responses where practical.
   - Keep tests focused on behavior rather than implementation internals.

4. Run targeted verification.
   - `pnpm test:unit -- auto-press`
   - `pnpm check:auto-press-agent-loop`
   - `pnpm check:planning`
   - `pnpm ci:typecheck`

5. Close the phase.
   - Write `15-01-SUMMARY.md`.
   - Update `.planning/STATE.md` with completed plan count and remaining Phase 16 entry point.

## Non-Goals

- Do not migrate the whole app runtime to Cloudflare.
- Do not redesign `/cam/auto-press` in this plan; that belongs to Phase 17.
- Do not remove `cp-auto-press-history` compatibility reads yet.
- Do not enable break-glass maintenance APIs or destructive migration scripts.

## Acceptance Criteria

- v3.0 requirements are reflected in `.planning/PROJECT.md`, `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, and `.planning/STATE.md`.
- Missing AI settings/key paths produce structured, operator-visible failure reason codes instead of uncaught exceptions.
- Auto-press targeted unit/route tests pass in the Linux working tree.
- Planning consistency guard passes with v3.0 marked active and v2.0 still complete.
