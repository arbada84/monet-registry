# Phase 18-01 Plan: D1 retry queue processor verification

## Goal

Close `AUTO-08` by verifying that AI retry processing uses the D1-backed `auto_press_retry_queue` and safely distinguishes retry targets before any AI/provider work begins.

## Context

Phase 17 completed manual run controls, dashboard coverage, and preflight health readiness. Phase 18 now verifies the retry and notification layer. The existing retry processor already reads D1 queue rows and can process both existing published articles and unpublished auto-press retry payloads. This phase tightens target classification so malformed or unknown queue rows become manual-review items instead of accidentally falling into provider/API paths.

## Tasks

1. Audit retry processing paths.
   - `src/lib/auto-press-retry-queue.ts`
   - `src/lib/auto-press-retry-target.ts`
   - `src/app/api/cron/retry-ai-edit/route.ts`
   - `src/app/api/auto-press/retry-queue/process/route.ts`

2. Verify D1 ownership.
   - Read due entries from `listDueAutoPressRetryQueue`.
   - Read forced entries from `getAutoPressRetryQueueEntry`.
   - Lock entries with `markAutoPressRetryQueueRunning`.
   - Complete/fail entries through D1 observability helpers.
   - Avoid broad article scans as a fallback.

3. Verify target safety.
   - Existing article rows continue through article AI re-edit.
   - Complete unpublished payloads create a new article only after AI edit and image checks.
   - Missing or malformed targets become `gave_up` manual-review entries before AI settings are read.

4. Add tests and static guards.
   - Add unit coverage for unknown retry targets.
   - Add target classifier coverage for incomplete unpublished payloads.
   - Extend `pnpm check:auto-press-agent-loop` with retry queue processor and target safety checks.

5. Run verification.
   - `pnpm test:unit tests/unit/auto-press-retry-queue.test.ts`
   - `pnpm check:auto-press-agent-loop`
   - `pnpm check:planning`
   - `pnpm ci:typecheck`
   - `pnpm ci:lint`
   - `pnpm build`

## Non-Goals

- Do not change Telegram command/report output; Phase 18-02 covers Telegram operations.
- Do not enable Vercel direct retry processing by default.
- Do not deploy or mutate live D1/Worker resources.
- Do not rework AI prompt or image processing behavior beyond target safety.

## Acceptance Criteria

- Retry processing is guarded as D1 queue driven.
- Unknown or malformed retry targets do not read AI settings or articles.
- Existing article and unpublished payload paths remain covered.
- Agent-loop, planning, typecheck, lint, and build checks pass.
