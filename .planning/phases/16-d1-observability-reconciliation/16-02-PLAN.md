# Phase 16-02 Plan: reconciliation and stuck-run behavior

## Goal

Close `AUTO-04` by ensuring stale queue-only auto-press runs cannot remain permanently `queued` or `running` when their D1 item state can no longer make progress.

## Context

Phase 16-01 proved that D1 run/item/event/retry/source quality paths and migrations are covered by guardrails. The existing reconciliation already handles orphaned runs with no item rows. It still needs stronger behavior for Worker queue edge cases:

- Worker acquired a lease and then died before releasing the item.
- A queued item reached `max_attempts` and is no longer eligible for Worker processing.
- Run counters drifted away from item terminal states.

## Tasks

1. Extend reconciliation behavior.
   - Keep the existing orphaned no-item run failure path.
   - Requeue expired running items when attempts remain.
   - Mark exhausted queued/running items as final failed items with `retryable=0`.
   - Refresh run counters after item reconciliation.
   - Append operator-visible D1 events with Korean messages and count metadata.

2. Preserve operational evidence.
   - Do not delete run/item rows.
   - Keep item-level reason codes/messages.
   - Use D1 `auto_press_items(status='fail', retryable=0)` as the DLQ operating model.

3. Add guardrails and tests.
   - Add unit coverage for exhausted items becoming DLQ-visible.
   - Add unit coverage for expired leases being requeued.
   - Extend the auto-press agent-loop guard so reconciliation reason codes cannot disappear silently.

4. Run targeted verification.
   - `pnpm test:unit -- auto-press-observability`
   - `pnpm check:auto-press-agent-loop`
   - `pnpm check:planning`
   - `pnpm ci:typecheck`

5. Close Phase 16.
   - Write `16-02-SUMMARY.md`.
   - Mark `AUTO-04` complete.
   - Mark Phase 16 complete and make Phase 17 the next active phase.

## Non-Goals

- Do not deploy or apply migrations.
- Do not change Cloudflare Queue infrastructure.
- Do not redesign `/cam/auto-press`; that is Phase 17.
- Do not remove `cp-auto-press-history` compatibility writes.

## Acceptance Criteria

- Stale no-item runs are failed with `QUEUE_ITEMS_MISSING`.
- Stale running items with remaining attempts are released back to `queued` with `WORKER_LEASE_EXPIRED`.
- Exhausted queued/running items are marked `fail`, `retryable=0`, and `QUEUE_ITEMS_STUCK` so they appear in DLQ routes.
- Run counters are refreshed after reconciliation.
- Tests and planning guards pass.
