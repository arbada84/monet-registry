# Phase 16-01 Plan: D1 observability schema and provider audit

## Goal

Close `AUTO-03` by proving the D1-backed auto-press run, item, event, retry queue, DLQ, and source quality paths are the primary operational record, with `cp-auto-press-history` kept only as compatibility history.

## Context

Phase 15 confirmed the v3.0 baseline and structured AI settings failures. Phase 16 now moves from failure classification to durable operational state. The current implementation already has D1 tables and helper APIs, but the schema/runtime contract needs an explicit guard so later Worker, dashboard, or retry changes cannot drift away from the migrations.

## Tasks

1. Audit D1 migration coverage.
   - Verify `auto_press_runs`, `auto_press_items`, `auto_press_events`, `auto_press_retry_queue`, `auto_press_source_stats`, and `auto_press_daily_usage` exist in migrations.
   - Confirm runtime columns used by Next.js helpers and the Cloudflare Worker are covered by additive migrations.
   - Keep existing production migrations immutable; add only a new additive migration if a gap is found.

2. Audit provider/helper coverage.
   - Confirm `src/lib/auto-press-observability.ts` owns run/item/event/retry/DLQ/source quality reads and writes.
   - Confirm `/api/auto-press/*` routes read D1 observed state rather than relying only on `cp-auto-press-history`.
   - Confirm Worker-created article rows can be traced back to the originating observed item.

3. Add guardrail verification.
   - Extend `scripts/auto-press-agent-loop-verify.mjs` with schema/runtime coverage checks.
   - Ensure required migration files and source quality/DLQ routes are included in the agent-loop guard.
   - Update Worker documentation to name the canonical migration set.

4. Run targeted verification.
   - `pnpm check:auto-press-agent-loop`
   - `pnpm check:planning`
   - `pnpm test:unit -- auto-press-observability`
   - `pnpm ci:typecheck`

5. Close the plan.
   - Write `16-01-SUMMARY.md`.
   - Mark `AUTO-03` complete and update Phase 16 progress.

## Non-Goals

- Do not change runtime provider selection for the whole app.
- Do not remove `cp-auto-press-history` compatibility writes yet.
- Do not implement stuck-run reconciliation beyond schema/provider coverage; that is `16-02`.
- Do not deploy or apply D1 migrations to production from this plan.

## Acceptance Criteria

- D1 auto-press migrations include all observation tables and the runtime indexes/traceability needed by Phase 16.
- Worker-created articles have a D1 schema slot for the originating `auto_press_items.id`.
- `pnpm check:auto-press-agent-loop` fails if a required auto-press D1 table, column, route, or migration file disappears.
- `AUTO-03` is marked complete in planning after verification passes.
